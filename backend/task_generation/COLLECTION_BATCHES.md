# 生成侧采集批次接口

普通任务生成和失败用例扩增可以把当前未删除的任务冻结成一个采集批次，保存完整 JSON 快照及统一的 17 列 Excel。批次提交只准备本地采集数据，不下发任务、不启动模型或手机。手机工厂页面新增批次选择，并复用现有上传和运行流程；Python client、手机控制协议与旧 Excel 导出保持原样。

动态读取当前结果继续使用 [collection-input 接口](COLLECTION_INPUT.md)。批次是提交时的固定版本；提交后再编辑或删除源结果，不会修改这个批次。

## 接口

以下路径均以 `/api/task-generation` 开头。JSON 成功及错误响应、工作簿下载均带 `Cache-Control: no-store`。

| 方法和路径 | 响应 |
| --- | --- |
| `POST /jobs/{job_id}/collection-batch` | 无请求体。首次创建返回 `201` 和批次详情；重复提交返回 `200` 和同一个已保存的详情。 |
| `GET /collection-batches` | 返回 `{"batches": [批次摘要]}`，按创建时间倒序排列。可使用 `?job_id=...` 查询某个来源作业，没有匹配批次时返回空数组。 |
| `GET /collection-batches/{batch_id}` | 返回 `200` 和批次详情，包含提交时冻结的任务。 |
| `GET /collection-batches/{batch_id}/workbook` | 返回已保存的 `.xlsx` 文件，不根据源作业重新生成。 |

每个来源作业只创建一个批次，`batch_id` 固定等于 `source_job_id`。重复提交不产生新批次、新时间或新文件；即使源任务后来有编辑、删除或状态变化，仍返回第一次提交的内容。当前不提供覆盖批次或二次版本接口。

## 摘要和详情字段

| 字段 | 类型和含义 |
| --- | --- |
| `schema_version` | integer，固定为 `1`。 |
| `batch_id` | string，批次 ID，等于来源作业 ID。 |
| `source_job_id` | string，来源生成或扩增作业 ID。 |
| `kind` | `task_generation` 或 `augmentation`。 |
| `job_status` | 提交时的 `succeeded` 或 `partial`。 |
| `knowledge_base_version` | 提交时来源作业的知识库版本，历史缺失时为 `null`。 |
| `created_at` | string，首次成功创建时记录的带时区时间。 |
| `task_count` | integer，冻结任务数量，包含未删除且有效的前置任务。 |
| `apps` | string array，任务涉及的 App，按任务中的首次出现顺序去重，不拆分或改写原 App 文本。 |
| `filename` | `collection-batch-{batch_id}.xlsx`。 |
| `download_url` | `/api/task-generation/collection-batches/{batch_id}/workbook`。 |
| `snapshot` | 仅详情返回。完整的统一采集输入 JSON，包含下面说明的批次编号字段。列表不包含这个对象。 |

`snapshot` 保留 [统一采集输入协议](COLLECTION_INPUT.md) 的顶层字段及全部任务字段，只为每条 `tasks[]` 增加一个非空字符串 `collection_case_id`。来源错误、提示、行级状态、种子身份、前置引用和未知依赖都留在 JSON 中，不会因投影为 17 列 Excel 而从快照中消失。

`collection_case_id` 的选择规则：

- 普通生成使用统一任务的 `task_id`，不采用可能存在的扩增用例编号。
- 失败扩增优先使用非空的 `case_id`（源字段“用例编号”）；缺失、`null` 或仅含空白时使用 `task_id`。
- 保留所选合法字符串的原值，不添加前缀、随机编号或重新排序的序号。
- 批次内所选编号必须唯一，包括已有用例编号与另一行回退编号之间的碰撞；冲突返回 `409`，不自动改号。

例如，历史扩增没有 `task_uuid` 和“用例编号”时，`task_id` 已由统一协议取源 `result_id`，其 `collection_case_id` 继续使用这个稳定 ID，不补造新身份。

## Excel 的 17 列

工作表固定为 `Sheet1`，列名和顺序如下。只填写前 7 列；第 8 至第 17 列保留空单元格，不填 `unknown`、`-2`、来源提示或推测内容。

| 序号 | 列名 | 值 |
| --- | --- | --- |
| 1 | 用例编号 | `collection_case_id` |
| 2 | 单APP跨APP | 固定文本 `单APP` |
| 3 | 涉及APP | `app` |
| 4 | 一级场景 | `scene`，缺失时为空 |
| 5 | 二级场景 | `capability`，缺失时为空 |
| 6 | 三级场景 | `sub_capability`，缺失时为空 |
| 7 | 任务 | 提交时已保存的 `task`，包含人工修改 |
| 8 | 难易程度 | 空 |
| 9 | 页面关键元素 | 空 |
| 10 | 预期步数 | 空 |
| 11 | 用例来源 | 空 |
| 12 | 构建人 | 空 |
| 13 | 任务结束标志 | 空 |
| 14 | 任务复杂度 | 空 |
| 15 | 关键动作 | 空 |
| 16 | SOP | 空 |
| 17 | 动态变量说明 | 空 |

前 7 列的非空值写为 Excel 文本单元格。以 `=`、`+`、`-`、`@` 开头的编号或文本仍是原始字符串，不执行公式，也不通过添加可见前缀改写内容。文本包含 Excel XML 禁止的控制字符，或超过单元格 32,767 字符限制时，提交返回 `409`，不静默截断源值。

弱依赖的 `pre_node` 和主任务都会出现在表中。强依赖任务也保留；其 `pre_dependency=strong`、原 `source_status="-2"` 只在 JSON 快照中保存，不填入这张表的空列。扩增未做依赖判定时仍为 `unknown`，不会被写成 `zero`。此格式不替采集执行端决定依赖任务如何运行。

## 校验、持久化与错误

首次提交沿用统一采集输入的校验：只接受 `succeeded`、`partial` 作业，读取当前持久化的未删除结果，检查稳定编号、任务/App 文本及完整的前置关系。页内筛选和旧 Excel 文件不影响提交内容。与动态读取接口允许空列表不同，批次至少需要一条有效任务。

| HTTP 状态 | 情况 |
| --- | --- |
| `404` | 提交时来源作业不存在；或读取、下载时指定批次不存在。 |
| `409` | 首次提交的作业状态不满足条件、未删除任务为空、源结果缺失/损坏、依赖引用不完整或统一协议字段无效。 |
| `409` | 所选采集用例编号重复，或前 7 列文本无法按原值写入 Excel。 |
| `409` | 批次目录或文件保存失败；或已有批次文件缺失/损坏。 |
| `409` | 批次编号或路径不合法。 |

错误体为 `{"detail": "具体原因"}`。调用方应使用 HTTP 状态判断结果，并显示实际原因。不能把 `409` 当作已经提交；也不会收到跳过坏行后的替代批次。

默认保存路径为 `backend_workspace/task_generation/collection_batches/{batch_id}/`，包含 `batch.json` 和下载文件名对应的 Excel。测试或独立部署可通过 manager 的 `collection_batches_dir` 参数指定目录；不指定时使用 `jobs_dir.parent / "collection_batches"`。

`batch.json` 另含内部 `_integrity` 对象，其中 `payload_sha256` 校验规范 JSON 表示的完整公开批次内容，`workbook_sha256` 校验工作簿字节。该对象只用于磁盘完整性检查，不出现在 API 摘要、详情或 `snapshot` 中。读取时校验哈希及摘要与快照的一致性；工作簿截断、替换或合法 JSON 内容被意外改写都会使该批次不可读取，详情、重复提交和下载返回 `409`，列表不纳入损坏批次，不自动用源任务重建。

同一个 manager 使用现有作业锁保护冻结与提交。系统先在批次根目录下的隐藏临时目录写完工作簿和元数据，再一次性发布完整目录。失败不会暴露半个新批次；批次列表忽略隐藏临时目录及损坏目录。已发布批次损坏时，读取或重复提交会明确报错，不用当前源数据静默重建它。

服务重启后直接读取保存的快照和工作簿。批次列表、详情和下载不写回数据，也不依赖重新读取源结果。冻结期间不会更新原生成作业、结果、已有导出或知识库文件；该接口不触发采集侧运行。

## 页面与手机采集接入

生成和扩增的结果审核区域提供“提交轨迹采集”。提交前沿用原页面的保存／放弃未保存修改流程；已提交作业展示批次编号、时间、数量、下载与“前往手机采集”。即使源任务后来全部被删除，这份批次仍可使用。跳转地址为 `/collection/phone-factory?collection_batch_id={batch_id}`。

手机采集的“生成任务批次”区域可选择、刷新、下载批次。选择时只读取批次；点击“开始运行所选批次”或确认“定制运行”后，才下载并上传 Excel，再调用现有运行接口。全部运行继续使用现有全部手机方式，定制运行继续使用所选手机和 App。本次没有增加依赖调度或远端完成回传；运行状态沿用采集模块原有规则。

现有 `POST /api/phone-factory/tasks` 增加可选 `source_batch_id`，其余上传字段仍为 `description`、`filename`、`content_base64`。批次文件名必须是 `collection-batch-{source_batch_id}.xlsx`，登记记录额外保存批次 ID 与内容 SHA-256。相同批次和相同内容重复上传返回原记录，保留包括“运行中”在内的状态；内容不同返回 `409`。手动上传保持可用，但不能占用批次文件名前缀或覆盖批次文件。

任务登记、启动状态和删除通过同一串行队列读写任务 JSON，文件原子写入；失败的导入不会启动手机。用户界面在下载、导入、运行期间限制重复操作，并拒收过期选择的结果。远端已经接受运行后，即使页面被关闭，也会继续尝试保存本地运行状态；失败会显示错误，不自动再次下发。

批次数据由 FastAPI 持久化，手机工厂接口仍由原 Vite 开发服务提供。本次不迁移该服务，也不更改其上传目录或 Python 运行配置。独立页面验收可以先构建前端，再运行 `python -m backend.tests.collection_batch_demo_server --port 8793`；该服务使用临时批次和内存手机接口，不向真实手机下发。
