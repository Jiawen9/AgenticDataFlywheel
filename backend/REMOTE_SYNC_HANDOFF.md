# 平台后台轮询修复与部署

本次只更新平台 backend。前端、9011、手机代码和模型配置均不需要同步修改。

## 行为

- 评估运行与生产采集回传共用持久化重试策略，但使用独立的后台工作线程，每条链路最多 2 个，不堆积历史任务队列。
- 正常同步间隔约 10 秒；失败后分别等待 30、60、120、300 秒，后续保持 300 秒。成功后恢复正常周期。
- 仅运行状态查询的明确 HTTP 404 才累计运行缺失。连续 3 次，且距实际下发已满 5 分钟后，暂停自动同步。结果与归档接口的 404 不按运行缺失处理。
- 已确认远端结束后，最终结果同步连续失败 8 次则暂停。已有完整最终结果不再请求远端。
- 新任务在实际发送启动请求前失败，不启动后台查询；旧记录缺少该标记时正常查询确认。
- 暂停及退避记录存放于既有数据库的 `remote_sync` 记录命名空间。重启后继续生效，无需修改数据库表结构。
- 页面结果查询遵守相同规则。有缓存时继续返回已有结果；查询异常时附带 `stale` / `sync_error`。无缓存时明确返回同步等待或不可用，不创建空结果。
- 同步异常不会启动或停止手机，不会删除轨迹、报告或历史记录，也不会把网络异常当作任务执行失败。
- 预期错误只在首次、类别变化、暂停及恢复时记录；未知错误的诊断堆栈限频。首次部署后可能仍看到少量历史错误，达到条件后才暂停，不是一启动就抹去全部诊断。

## 查看与手动恢复

原运行列表接口新增可选 `sync` 字段：

- `state`：`active` 正常、`backoff` 等待重试、`paused` 暂停、`complete` 同步完成。
- `pause_reason`：`remote_missing` 远端运行缺失、`final_sync_exhausted` 最终结果补取耗尽。
- `next_retry_at`、`last_success_at`、`last_attempt_at`：UTC 时间。
- `last_error`、`last_error_category`：最近错误摘要与分类。
- `failure_count`、`not_found_count`、`final_failure_count`：相应计数。

确认平台连接的是正确的 9011、远端记录或网络已恢复后，可以使用现有同步接口：

```text
POST /api/model-iter/runs/<eval运行编号>/sync
POST /api/phone-factory/collection-runs/<cr运行编号>/sync
Content-Type: application/json
请求体：{}
```

请求发送给平台后端，不直接发送给 9011。原有访问认证方式保持不变。手动同步解除暂停并尝试一次，失败后重新退避，不生成新的采集运行。若已有同运行同步在途，将合并等待；跨进程争用或超过等待时间会提示稍后再查，不重复启动同步。

平台对外上游错误仍兼容原有 HTTP 502；内部已保留真实远端状态、调用阶段和超时类别。不要仅凭浏览器显示的 502 判断运行不存在。

## 上线与回滚

1. 备份平台当前代码和数据库（数据库位置以实际 DATA_ROOT 为准）。
2. 同步本次 backend 修改及新增文件，特别是 `remote_sync.py`，不能只替换旧文件。
3. 重启平台后端。无需更新前端或 9011，也不需要新增环境变量。
4. 验证一个正常评估和一个采集回传运行仍更新；观察旧 404 从有限重试进入暂停。
5. 核对重启后暂停仍有效，再对一条已恢复的运行调用手动同步接口。

若回滚，恢复此次代码修改前的版本并重启平台后端即可。新增同步记录不会修改历史轨迹或结果；旧代码不读取这些记录。无需为了回滚删除历史数据或清空数据库。

## 验证边界

本地测试使用模拟 9011 和临时数据库，不代表已经完成内网实测。本次不修复采集端自身的任务表、yadb、网络预检或状态查询持锁问题；如果当前有效运行仍频繁超时，应进一步核对 9011。

原基线已存在两项回归失败，本次不扩大范围修改：

- `test_failed_transfer_does_not_hide_other_live_run_and_remains_actionable`：另一条运行回传失败时，任务列表的展示状态与测试期望不一致。
- `test_old_service_rejected_and_same_run_recovers_after_lost_response`：生产采集的服务能力缓存仍为不支持，未进入测试预期的回执丢失分支。

两项已在未修改的平台代码上单独复现。本次核心回归 118 项中 116 项通过，另外两项为上述基线失败；完整模拟联调 21 项全部通过，合计 139 项中 137 项通过。

核心回归覆盖持久化退避、连续 404 与宽限期、最终结果补取上限、错误阶段隔离、手动恢复、页面刷新限流、并发去重、有限后台线程、取消和最终快照恢复。模拟联调覆盖实际 Flask 请求契约、独立评测、生产回传、摘要与归档、Logprobs、Pipeline、标注及发布流程。
