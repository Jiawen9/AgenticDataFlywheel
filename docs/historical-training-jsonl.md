# 历史训练 JSONL 后台回流

在内网平台后端所在电脑登记已经训练过的 JSONL。登记成功后，「数据发布 → 历史发布」显示名称和版本，详情里的「来源文件」显示原文件名及已有云道地址，可从训练文件区下载原始 JSONL。总览汇总完成后，在「训练数据总览 → 数据来源」可分别筛选数据飞轮、工厂、健康云和 middle。

## 内网操作

1. 将[清单模板](historical-training-jsonl.example.json)复制到内网数据目录并改名为 `historical-training-jsonl.json`。将 `file`、`name`、`version`、`data_source` 和 `cloud_uri` 改为实际值。文件路径可以用绝对路径，或按清单目录写相对路径。云道填写 `s3://bucket/对象或目录`，使用已有地址。
2. 如已知日期及分类，给对应条目补充 `data_date`（YYYY-MM-DD）、`app`、`level1`、`level2`。缺日期时按首次登记日期，缺分类使用「未记录 App／未分类」。日期和地址以清单为准。
3. 在包含 `backend/` 的平台项目根目录，用平台环境先运行预检，再加 `--apply` 登记。运行命令时使用平台服务相同的 `ADF_DATA_ROOT`。

```powershell
python -m backend.data_publishing.historical_jsonl 'D:/historical-training/historical-training-jsonl.json'
python -m backend.data_publishing.historical_jsonl 'D:/historical-training/historical-training-jsonl.json' --apply
```

预检列出样本、轨迹、分类、单步归组和异常行。确认预检数字后再登记。命令向同一数据目录的本机后端请求排队汇总，默认使用 `http://127.0.0.1:8765`，可用 `--api-url` 指定实际的本机地址。后端离线时，待其启动会检查尚未转换的发布。汇总状态和重试沿用发布详情的入口。历史列表沿用现有「外部表格」徽标，规模显示 0 份 Excel，可点击详情下载 JSONL。

## 统计和追溯

- 四个清单条目各自保留版本与统计。同一数据来源、版本及相同内容和配置再次执行时复用原记录。工厂和健康云是两个独立来源，即使摘要相同也分别计入。
- 每条有效 JSONL 记录计一个步骤。先用明确轨迹 ID，再用格式对应的图片路径或连续历史分组。其余按独立单步轨迹统计，步数分布显示为 1。人工精修从明确的逐样本标记读取，缺失时记为未知。
- 原 JSONL 与摘要随发布冻结，训练下载返回原字节。转换报告包含原行号、排除数及统计口径。云道地址为已登记的来源元数据，页面上传状态仍由现有上传任务记录决定。
- 内网全量文件、填写实际地址的清单和原始样本保留在内网。代码仓库只需同步通用模板、后端和说明。

本地验证通过 151 项相关后端测试。四份样本通过实际本机后端完成预检、登记、下载和来源筛选，汇总为 4 个发布、24 个步骤、16 条统计轨迹。原件下载逐字节一致，重复登记后的发布编号和计数保持一致。正式内网全量文件待现场预检。
